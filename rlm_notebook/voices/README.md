# Reference voices for the `chatterbox` TTS provider

Two ten-second WAV clips. They are the only way this project can put **two distinguishable hosts**
in an Audio Overview when `RN_TTS_PROVIDER=chatterbox`: Chatterbox ships exactly one built-in voice
(`conds.pt` in its checkpoint), and every other voice comes from cloning a reference clip. Naming
both hosts the built-in voice would turn a two-host episode into a monologue in two halves.

The clips carry **timbre only**. Their words are never heard in a generated episode — the model
reads them to learn how the voice sounds, then speaks whatever the script says, in whatever language
the notebook resolved to.

## Where they came from, and the part worth reading

Both were **synthesized by Kokoro** (`hexgrad/Kokoro-82M`, Apache-2.0), from voices `am_adam` and
`af_heart`, with the script at the bottom of this file — the same model this project shipped as its
local provider until Chatterbox replaced it. **No person was recorded to make them**, which is the
point: cloning a real human's voice raises a consent question that the licence on a recording does
not answer, and it is a question this project is in no position to answer for someone else.

**The disclosure that belongs here, because it is not spotless.** Kokoro's own model card states its
training data includes *"synthetic audio generated by closed TTS models from large providers"*. So
the provenance chain behind these two clips is three hops long — closed TTS output, into Kokoro's
training set, into these clips, into a Chatterbox clone. Every hop is permissively licensed as
distributed, and no human voice is being appropriated at any of them; but this project has already
paid once for taking a licence chain on trust (the AGPL/`pymupdf` incident, AGENTS.md invariant 7),
so the chain is written down rather than left for someone to discover.

If that chain is not acceptable for your deployment, `RN_TTS_VOICE_HOST_A` / `RN_TTS_VOICE_HOST_B`
accept an **absolute path** to your own reference `.wav` and these files are then never read. That
override is environment-only and deliberately unreachable from the settings page — a path arriving
through an unauthenticated HTTP endpoint would be an arbitrary-file-read surface (AGENTS.md
invariants 26 and 41).

Setting either to `built-in` uses Chatterbox's own voice instead.

## Why ten seconds

`ChatterboxMultilingualTTS.DEC_COND_LEN` is `10 * 24000` samples and `ENC_COND_LEN` is `6 * 16000`,
so past ten seconds only the speaker-embedding encoder reads any of it. Longer clips would cost
wheel size and buy nothing.

## Regenerating them

Needs `kokoro` and `misaki[zh]`, which this project no longer depends on — install them into a
throwaway environment rather than the project's. The text is never heard; it says what the file is
so anyone who opens it knows immediately.

```python
import wave, numpy as np, pathlib
from kokoro import KPipeline

TEXT = ("This is a reference recording for a synthetic podcast host. It carries the timbre of the "
        "voice and nothing else. No person was recorded to make it.")
OUT, SR = pathlib.Path("rlm_notebook/voices"), 24000
pipeline = KPipeline(lang_code="a")
for name, voice in (("host_a.wav", "am_adam"), ("host_b.wav", "af_heart")):
    audio = np.concatenate([r.audio.numpy() for r in pipeline(TEXT, voice=voice)])[: SR * 10]
    with wave.open(str(OUT / name), "wb") as handle:
        handle.setnchannels(1)
        handle.setsampwidth(2)
        handle.setframerate(SR)
        handle.writeframes((audio * 32767).astype("<i2").tobytes())
```
